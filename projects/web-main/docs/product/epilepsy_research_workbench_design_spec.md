# 癫痫科研分析工作台设计规范

适用对象：面向科研客户的 EEG/癫痫相关数据分析平台、研究项目分析工作台、批量数据处理与结果复核界面。

不适用对象：临床诊断系统、医生诊断辅助系统、医疗器械级报告系统、内部研发调试后台。

## 核心总规范

癫痫科研分析工作台的所有功能，都必须围绕：

- 输入清楚
- 分析可控
- 结果可解释
- 方法可追溯
- 导出可复现

来设计。

默认呈现科研决策所需的信息，按需展开复现和调参所需的信息，隐藏工程实现和系统噪音。

## 1. 产品定位

本系统是科研分析工作台，不是临床诊断系统。

界面和导出不得输出：

- 确诊
- 诊断为
- 患者已患
- 治疗建议
- 临床结论

所有结果应表述为：

- 科研分析结果
- 候选事件
- 疑似片段
- 统计特征
- 复核建议
- 数据质量影响
- 方法参数记录

## 2. 用户角色

### 2.1 研究者

主要任务：

- 上传或选择 EEG/实验数据。
- 设置分析参数。
- 查看分析进度。
- 判断数据质量是否足够。
- 查看异常事件、频段特征、通道特征、时间片段等结果。
- 导出图表、表格、方法记录和报告材料。

设计重点：

- 默认界面要清楚、可信、可追溯。
- 需要保留参数、方法、QC、版本信息，但不能把它们全部放在主视图。

### 2.2 高级分析用户

主要任务：

- 调整预处理参数。
- 对比不同算法或参数组。
- 查看中间结果。
- 做批量分析、队列管理、结果复核。

设计重点：

- 提供高级设置、方法详情、结果对比、批量操作。
- 高级能力不得干扰普通研究者的主流程。

### 2.3 管理员或支持人员

主要任务：

- 查看任务状态、错误、资源占用、审计日志、用户权限。

设计重点：

- 管理信息进入管理后台。
- 不要把服务器日志、部署状态、内部错误堆到科研客户主工作台。

## 3. 总体信息架构

所有功能页必须按同一信息优先级组织：

1. 当前研究任务是什么。
2. 用户需要输入什么。
3. 数据是否可分析。
4. 分析正在做什么或已经完成什么。
5. 结果是什么。
6. 结果基于哪些数据、参数、方法和版本。
7. 用户下一步可以做什么。

主界面允许优先出现的信息类型：

- 当前研究任务。
- 数据输入状态。
- 参数或预设状态。
- 分析进度。
- 数据质量 QC。
- 核心结果摘要。
- 关键证据图表。
- 下一步操作建议。
- 导出入口。
- 可追溯信息入口。

主界面不应默认出现的信息类型：

- 后端任务 ID。
- 服务器日志。
- 容器状态。
- 原始异常栈。
- 数据库 ID。
- 内部调试按钮。
- 大量未解释统计量。
- 过细算法内部参数。
- 与当前任务无关的导航、广告式说明或功能宣传。

## 4. 页面结构规范

每个功能页必须包含：

- 输入模块。
- 参数模块。
- 分析状态模块。
- QC 质量控制模块。
- 结果摘要模块。
- 证据或图表模块。
- 方法与参数追溯模块。
- 导出模块。

### 4.1 推荐主布局

科研分析页建议使用三层工作台结构。

顶部任务栏显示：

- 项目名称或样本名称。
- 数据类型。
- 分析状态。
- 最近保存时间。
- 主要操作按钮：上传、开始分析、保存参数、导出。

要求：

- 顶部任务栏始终回答“我现在在哪个任务里”。
- 主要按钮不得超过 3 个。
- 次要操作放入更多菜单或侧边抽屉。

左侧输入与参数区显示：

- 数据文件。
- 必填元数据。
- 预处理配置。
- 分析模块选择。
- 参数预设。

要求：

- 默认显示必要输入和常用参数。
- 高级参数折叠在高级设置中。
- 每个输入项要有状态：未填写、已填写、异常、可选。

中央结果与证据区显示：

- 结果摘要。
- 关键图表。
- 时间轴。
- 事件列表。
- 通道、频段、片段级证据。

要求：

- 结果摘要必须在图表之前或与图表并列出现。
- 图表必须有明确标题、单位、时间范围、通道范围和参数来源。
- 图表不能只“好看”，必须服务于科研判断。

右侧辅助与复现区显示：

- 数据质量 QC。
- 方法摘要。
- 参数摘要。
- 版本信息。
- 导出清单。
- 下一步建议。

要求：

- 用状态卡片或折叠面板组织。
- 不抢中央结果区的视觉优先级。
- 复现信息必须可复制、可导出。

## 5. 输入、参数、状态、结果、导出

### 5.1 输入模块

每个输入模块必须回答：

- 用户需要提供什么？
- 是否已经提供？
- 当前输入是否满足分析要求？
- 缺失或异常时如何修复？

输入模块状态：

- Ready：可分析。
- Missing：缺少必要输入。
- Warning：可继续，但结果可能受影响。
- Error：不能继续。

错误信息必须告诉用户如何修复，不显示内部异常栈，不使用只有开发者能理解的字段名。

推荐：

> 通道信息缺失，无法计算通道级特征。请上传通道表或选择默认 10-20 通道模板。

不推荐：

> channel_map parse failed: null

### 5.2 参数模块

参数分为三层：

- Preset：预设，默认展示。
- Common：常用参数，默认可见。
- Advanced：高级参数，默认折叠。

每个参数必须包含：

- 参数名。
- 当前值。
- 单位。
- 默认值。
- 参数说明。
- 是否影响可复现结果。

参数修改后必须提示：

- 结果是否需要重新计算。
- 哪些图表会受影响。
- 是否会产生新的分析版本。

### 5.3 分析状态模块

分析状态必须面向科研任务，而不是面向后端实现。

推荐状态：

- Waiting for input。
- Ready to run。
- Running preprocessing。
- Running feature extraction。
- Running event detection。
- Generating figures。
- Completed。
- Completed with warnings。
- Failed。

不推荐状态：

- celery pending。
- job id failed。
- worker timeout。
- container exited。

如果需要给支持人员查看内部状态，应进入技术详情或管理后台。

### 5.4 结果模块

结果模块必须遵循“摘要优先、证据其次、详情可展开”。

展示顺序：

1. 结果摘要。
2. 关键证据。
3. 详细图表。
4. 方法、参数、版本、QC 细节。

结果摘要必须包含：

- 分析对象。
- 分析方法。
- 分析时间范围。
- 关键发现。
- 数据质量影响。
- 是否建议复核。

结果证据可包含：

- 时间轴。
- 事件列表。
- 波形片段。
- 时频图。
- 频段统计。
- 通道拓扑图。
- 指标分布。
- 参数对比。

结果详情可包含：

- 计算公式。
- 阈值。
- 算法版本。
- 预处理步骤。
- 排除片段。
- 失败片段。
- 数据质量明细。

### 5.5 导出模块

科研工作台的导出是主流程的一部分。

必须支持：

- 图表导出。
- 表格导出。
- 参数导出。
- 方法摘要导出。
- 分析 manifest 导出。
- 完整结果包导出。

导出前必须显示：

- 包含哪些内容。
- 数据范围。
- 参数版本。
- 方法版本。
- 生成时间。

导出文件命名应包含：

- 项目或样本标识。
- 分析类型。
- 参数版本或运行编号。
- 日期时间。

## 6. 科研可信度与追溯

每个结果必须能追溯到：

- 原始文件。
- 文件标识或哈希。
- 上传时间。
- 采样率。
- 通道列表。
- 有效分析时间范围。
- 排除片段。
- 预处理流程。
- 算法名称。
- 算法版本。
- 参数版本。
- QC 规则。

### 6.1 QC 质量控制

QC 信息必须分层：

- 主界面显示总体 QC：通过、警告、失败。
- 展开后显示具体问题。
- 高级详情显示通道级、时间片段级、规则级 QC。

QC 必须说明对科研结果的影响。

不要只写“质量差”。要写“哪个通道、哪个时间段、影响什么分析”。

示例：

> Fp1 通道在 12.4% 的时长中存在高幅值伪迹，前额区功率分析可能偏高。

### 6.2 版本管理

用户修改参数或重新分析时，必须产生可区分版本。

版本记录应包含：

- 运行时间。
- 操作者。
- 输入数据版本。
- 参数版本。
- 算法版本。
- 结果状态。
- 是否为当前推荐版本。

## 7. 可视化设计规范

科研图表分为三类：

- Primary chart：支撑核心结论的图。
- Diagnostic chart：帮助解释或排查问题的图。
- Supplementary chart：补充分析图。

主界面最多同时突出 1-2 个 Primary chart。其他图表进入标签页、折叠区或详情页。

每张图必须包含：

- 标题。
- 坐标轴。
- 单位。
- 时间范围。
- 通道范围。
- 参数来源。
- 导出按钮。

禁止：

- 无单位颜色条。
- 未解释缩写。
- 只放图不说明数据范围。
- 所有图表同等视觉权重。

颜色语义必须稳定：

- 蓝色：信息、选中、当前范围。
- 绿色：通过、可用、完成。
- 黄色或琥珀色：警告、需注意。
- 红色：错误、失败、不可继续。
- 紫色或强调色：研究发现、高亮事件，可少量使用。

关键图表应支持：

- 缩放。
- 平移。
- 框选时间范围。
- 悬浮查看值。
- 点击定位事件。
- 导出当前视图。

交互状态必须明确：

- 当前选中片段。
- 当前筛选条件。
- 当前图表使用的参数版本。

## 8. 事件列表规范

每条事件至少显示：

- 时间。
- 持续时长。
- 通道。
- 类型。
- 指标值。
- 复核状态。

并支持：

- 时间排序。
- 强度或置信度排序。
- 通道筛选。
- 类型筛选。
- 点击跳转到波形或图表。

## 9. 文案规范

推荐用语：

- 分析。
- 检测。
- 特征。
- 候选事件。
- 疑似片段。
- 统计结果。
- 复核。
- 数据质量。
- 方法参数。

避免用语：

- 确诊。
- 诊断为。
- 患者已患。
- 治疗建议。
- 临床结论。

如必须出现医学术语，应限定为科研分析语境。

推荐：

> 在当前参数下，系统检测到 18 个候选癫痫样事件，主要分布在 T3/T4 相关通道。建议复核 00:12:31-00:14:08 时间段。

不推荐：

> 患者存在癫痫发作。

按钮应使用明确动词：

- 上传数据。
- 开始分析。
- 保存参数。
- 重新运行。
- 查看详情。
- 导出结果。
- 复制方法。
- 添加到报告。

避免上下文不清的按钮：

- 确认。
- 处理。
- 提交。
- 下一步。

## 10. 组件规范

所有模块尽量复用这些组件或等价结构：

- TaskHeader：任务身份与主操作。
- InputStatusPanel：输入状态。
- ParameterPanel：参数设置。
- AnalysisProgress：分析进度。
- QCPanel：质量控制。
- ResultSummary：结果摘要。
- EvidenceViewer：图表与证据。
- EventTable：事件列表。
- MethodsPanel：方法与参数追溯。
- ExportPanel：导出。

所有分析模块都要复用同一套状态、参数、QC、导出和版本模式，避免每个模块各自设计。

## 11. 权限与可见性

功能按用户角色分层：

- 研究者可见：输入、参数、结果、QC、导出。
- 高级用户可见：高级参数、版本对比、中间结果。
- 管理员可见：任务日志、系统错误、资源状态、审计记录。

默认客户界面不得显示：

- API Key。
- 服务端路径。
- 容器名。
- 原始异常栈。
- 数据库 ID。
- 内部调试按钮。

## 12. 响应式与密度规范

科研工作台通常用于桌面端，应优先优化 1440px 以上宽度。

桌面端：

- 使用多栏布局。
- 保留图表可读面积。
- 参数和 QC 可作为侧栏。

平板端：

- 左侧参数区可折叠。
- 图表和结果优先。

移动端：

- 只支持查看任务状态、摘要、导出状态。
- 不强行承载复杂波形分析。

## 13. 功能上线前检查

每个新功能上线前必须问：

1. 它属于输入、参数、状态、结果、证据、QC、方法、导出、管理中的哪一类？
2. 它是否必须出现在主视图？
3. 普通研究者是否默认需要它？
4. 高级用户是否需要展开后看到它？
5. 它是否影响可复现性？
6. 它是否需要进入导出或 manifest？
7. 它是否有失败状态和恢复路径？

功能验收清单：

- 页面第一眼是否能看出当前研究任务。
- 是否明确显示用户需要输入什么。
- 是否明确显示数据是否可分析。
- 是否能解释结果来自哪些数据和参数。
- 是否有 QC 状态。
- 是否有导出入口。
- 是否有方法、参数、版本记录。
- 是否隐藏了工程实现细节。
- 参数修改是否提示影响范围。
- 失败状态是否告诉用户如何恢复。
- 图表是否有标题、单位、范围和导出。
- 文案是否避免临床诊断措辞。

如果一个功能不能回答以上问题，先不要放进主工作台。
