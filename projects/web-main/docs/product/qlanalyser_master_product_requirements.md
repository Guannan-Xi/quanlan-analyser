## 1. 文档目的、分工与维护规则

### 1.1 文档目的与产品背景

脑电分析既要求选择合适的方法，也要求使用者理解分析代码、方法原理、参数含义和完整流程。许多目标用户不熟悉相关代码和原理，面对不同数据、方法和参数时，学习成本与实际操作成本较高。这些判断来自当前产品建设过程和团队内部实践观察，尚未在真实用户中验证，需要在后续访谈和试用中逐条确认。

产品面向做神经电生理研究的团队：高校和科研院所实验室、医院科研部门和临床研究团队、科研服务与独立分析团队。团队内部的具体角色分工和优先支持场景本章只写到团队粒度，客户优先级和验证安排见第二章。

产品首先要解决分析引导问题：用图形化、流程化的界面把分析拆成可见步骤，逐步说明当前在做什么、关键参数起什么作用、需要哪些质量检查、有哪些风险提示以及下一步是什么。这不是黑箱自动分析：界面降低操作和记忆负担，但不替代对方法的理解和使用者的专业判断。在分析引导之上，还要解决数据记录、结果复现、访问权限和备份问题，使同一份数据和参数能够被复核和重跑。平台的价值不在于包装某个开源算法，而在于提供可审查、可复核、可复现、可规范交付的科研流程。

QLanalyser 是科研辅助工具，不输出临床诊断结论，也不替代机构自身的合规责任，具体边界见第二章和附录。当前起点不是从零开发，已有基础见第三章。本文回答四个长期问题：为什么做见本章，定位与科研边界见第二章，现有基础见第三章，产品形态与各阶段推进条件见后续章节。正文说明长期方向和阶段判断，附录承载术语、规则、详细需求与待确认项。

## 2. 产品定位、客户与科研边界

**核心定位：QLanalyser 是面向神经科学研究的综合科研平台。** 长期范围包括神经电生理科研辅助分析、头皮脑电专业分析、电场仿真、Spike 和原始数据备份存储；统一承载研究对象、数据版本、任务、结果、报告、审计与后续协作。

优先服务高校和科研院所实验室、医院科研部门和临床研究团队，以及 CRO、科研服务团队和独立分析团队。具体客户优先级、采购路径和付费意愿仍需访谈与实际使用验证，本文不假设市场规模、客户数量或收入。

QLanalyser 不是临床诊断系统，不输出临床诊断或治疗建议。癫痫阈值/ML 科研筛查和 qEEG 结果只能作为科研筛查参考，必须保留“非诊断用途”提示。QEEG 工作流支持选择 19、32、64 三类导联配置，但每类配置必须分别定义通道映射、参考、QC、适用常模和验证状态；现有 19 导常模不得外推为 32 或 64 导常模，未通过对应常模验证时不得输出常模 Z-Score 或宣称常模有效。头皮脑电专业分析（scalp EEG）的参考、插值、ICA/ICLabel 和 QC 流程不得直接用于 SEEG/ECoG。公共头模结果不代表个体电场分布。不得把 draft、internal_validation 或 beta 生命周期的方法包装为稳定临床结论；不得把自动算法标签描述为已经人工确认。方法的“已实现”“可运行”和“科学验证通过”必须分开表述。完整规则分布在附录 A—G，各节标注唯一真源。

## 4. 五条业务线与统一平台关系

五条业务线保持独立定义和成熟度判断，共用平台公共能力，不等于五套产品，也不表示同时开发：

| 业务线 | 长期方向 | 当前阶段判断 |
| --- | --- | --- |
| 神经电生理科研辅助分析 | 数据管理、EMG、ECG/HRV、睡眠分期、癫痫科研筛查、QEEG 19/32/64 导联配置与报告；常模按配置独立验证 | 本地阶段 V1 迁移与产品化；正式名称待定 |

| Spike | 胞外电生理记录的 sorting、审核与下游分析 | 独立业务线；当前暂缓、不实现、不定价、不进入排期 |
| 电场仿真 | SimNIBS 个体头模与公共头模仿真 | 本地阶段 V2 完成流程与验证 |

平台分两层承载这五条业务线：公共层负责一致的数据、版本、安全和交付规则；专业服务层负责各领域输入、QC profile、方法、参数、验证证据和结果解释。公共层不能抹平专业差异。分层结构图见附录 C.0。

## 5. 长期产品形态

长期形态是一套从本地验证走向线上服务的综合科研平台，而不是本地版与线上版永久并行的两套产品。

本地形态应在无网络、无账号、无收费服务的条件下完成项目管理、数据导入、QC/复核、单方法分析或仿真、任务追踪、结果查看、复现材料和结果包导出。它首先用于验证技术链路、科学契约、用户流程和产品价值。

在本地产品及相应领域模块完成技术、科学和产品验证后，平台再演进为线上服务形态：增加身份与组织、多租户隔离、在线上传、异步资源调度、团队权限、审计、计量、账务、长期存储和真实备份容灾。线上服务不是简单部署本地界面，也不能先于领域验证上线收费。

无论形态如何变化，同一项目模型、方法 ID、输入输出契约、ArtifactManifest、版本追溯和安全边界应尽量保持稳定；运行环境、存储、任务执行、身份和计费通过适配层替换。线上权限和备份对象必须由服务端强制隔离，前端隐藏入口不构成安全边界。

## 6. 两阶段产品路线与版本

全产品只分两个阶段：本地阶段与线上阶段。数据不可变性、科研边界与安全要求不因阶段变化，两个阶段共用同一套规则（见附录 A—G）。

### 6.1 本地阶段：验证和产品化

三个版本在同一个离线本地 Web 产品壳中顺序推进，而不是三条平行分支：

1. **本地 V1：神经电生理科研辅助分析 Web 化。** 迁移 pc-qlanalyser 已验证逻辑，建立项目、数据版本、任务、报告、导出和本地备份/恢复模型，并提供 QEEG 19/32/64 导联配置选择；不包含本地 V3 的头皮脑电专业方法与自动 QC 体系、SimNIBS 或 Spike。
2. **本地 V2：电场仿真。** 加入 SimNIBS 个体/公共头模输入检查、参数配置、求解、比较和复现交付。
3. **本地 V3：头皮脑电专业分析。** 迁移 web-main 已有方法并落地自动 QC、标准去噪、SafetyGate、清洗版本冻结复用和专业结果契约。

本地阶段不提供线上服务，不建设或启用收费系统。每个版本都必须用去标识化代表性样本完成技术可运行、科学数值/契约验证和端到端产品验收；详细版本范围见附录 D.1—D.3，用户流程与边界见附录 D.4—D.6，验收证据见附录 D.7。

### 6.2 线上阶段：从单用户服务到规模化运营

线上阶段不与本地阶段无条件同步开发。某个领域模块只有完成本地技术验证、科学验证、产品验收和安全审查后，才允许进入线上版本。

```text
本地模块通过技术验证
+ 科学验证
+ 产品验收
+ 安全审查
        ↓
该模块才允许进入线上版本
```

线上阶段按以下四个版本顺序推进：

1. **Online V1：单用户在线分析。** 提供注册登录、项目与数据上传、云端异步计算、结果查看与下载、用量记录；不正式收费。完成条件是代表性本地工作流能够在隔离环境中稳定、安全地在线运行。
2. **Online V2：团队协作。** 提供组织/实验室、成员、项目权限、共享、审核、交付和审计记录，明确 PI、项目负责人和数据负责人。完成条件是真实科研团队能够按权限完成协作与交付。
3. **Online V3：商业化运营。** 提供套餐、计量、订单、支付、退款、发票、客户开通、销售线索和售后流程。进入条件是 Online V1/V2 已通过验收、账务一致性和目标客户付费意愿得到验证。
4. **Online V4：数据保护与规模化。** 提供独立备份、恢复演练、完整性校验、RPO/RTO、监控告警、故障处置，以及容量、性能、成本和安全治理。完成条件是服务达到经验证的持续运营和规模扩展要求。

每个 Online 版本均必须明确进入条件、范围、明确不做、技术与安全要求、验收责任人、完成条件和下一版本放行结论。线上阶段启动前必须满足：

- 本地端到端流程稳定；
- 方法与结果契约有证据；
- 安全和数据治理方案可实施；
- 目标客户和使用频率得到验证；
- 云资源与运维成本经过真实压测；
- 团队具备持续运营能力。

各项证据阈值和批准人列入正文 9.2 第1项待决策；在其确认前不得把上述检查项解释为已经放行。

线上启动后按 Online V1—V4 推进，不跨版本提前开放收费或作出容灾承诺。不得以尚未验证的本地模块进行线上收费。

SEEG/ECoG 在头皮脑电专业分析之后按独立专业模块推进，必须建立自己的电极模型、参考、QC、安全规则和真实样本证据。Spike 继续独立暂缓，直到获得合规、去标识化真实样本并重新完成需求和技术评估。

## 7. 商业方向

候选收入结构包括：按分析或仿真任务收取服务费；按长期活跃存储或原始数据备份容量与周期收费；超出套餐的下载流量；组织级服务；必要的实施、培训和专家复核服务。不同业务线可以共用账务基础设施，但不必共用同一计费单位。

验证原则是：先证明本地产品能稳定完成科研任务，再验证客户愿意为何种交付付费；先以 usage ledger 记录真实用量，再设计收费、退款和优惠；价格必须覆盖计算、存储、流量、人工、许可证、销售、运维、税费和失败重跑，不能只看直接云成本毛利；正式报价必须基于真实压测、采购询价和客户访谈复核。

现有“5元/数据小时/分析方法”“SimNIBS 个体头模 2000元/单、公共头模 200元/单”等数字均为内部测算假设，不是已确定对外价格，也不构成报价承诺。候选计费规则与内部价格假设见附录 F.1，阿里云直接成本模型见附录 F.2。

## 8. 拟构建的长期能力与壁垒

这里描述的是拟构建能力，不代表已经形成壁垒，更不主张独家算法：

- 跨模态但不混淆专业边界的数据与版本系统；
- 输入、参数、软件版本、处理步骤、哈希、警告和输出齐全的单方法工作流；
- 产品状态、运行状态与科学验证状态分离；
- QC、SafetyGate 与人工复核协同；
- 结构化数据、科研图、报告、方法说明和复现包组成的结果契约；
- 可审计、不可篡改的数据治理体系（数据不变量、分析与备份隔离、审计不可变性），形成医院与临床客户可核验的信任基础（具体约束见附录 A.3—A.4、E.5、G.1—G.3）。

**测试与交付资产**：仅积累自有、公开许可或客户明确授权可用于测试的去标识化样本，以及相应数值 golden、失败案例、契约测试和交付模板；明确排除未经授权的客户数据及其派生数据。

这些能力只有在真实项目中持续被使用、验证并形成明显的迁移成本或信任优势后，才能判断是否构成壁垒。

## 9. 核心风险与战略待决策

### 9.1 核心风险

- 科研功能被误解为临床诊断，或方法成熟度与运行成功被夸大；
- 不同模态错误复用同一 QC、参考或解释规则；
- 迁移历史代码库时形成第二套产品壳、重复工作流或不可追溯旁路；
- 本地流程尚不稳定就投入云端商业化；
- 医院科研数据的加密、访问控制、保存周期和跨区域要求未专项确认；
- 备份模型验证被误宣传为真实容灾，或 RPO/RTO 未经演练即作承诺；
- 内部价格假设只覆盖直接云成本；
- 五条业务线同时展开导致资源分散，特别是 Spike 过早进入排期。

### 9.2 战略待决策

## 附录 A：状态、术语与统一数据模型

本附录是全产品统一定义。产品需求状态、方法生命周期和单次运行状态不得混用；执行成功不等于科学验证通过。

### A.1 状态与生命周期标签

本文档区分三类正交的状态维度，不得混用：

**A. 产品需求状态**（本文档中标注功能所处的产品决策阶段）：
- **已确认**：产品规则已确认，可进入设计；
- **代码已存在**：当前代码库存在实现或可复用基础，不等于已产品验收；
- **规划中**：长期产品目标，尚未完成专项设计或验证；
- **待决策**：仍需产品负责人确认；
- **暂缓**：保留需求与架构接口，不进入当前阶段开发；
- **不在本地阶段**：本地阶段不实现，线上阶段或以后处理。

**B. 方法/模块技术生命周期**（某个分析方法的成熟度，与产品状态无关）：
draft 草稿开发中 / internal_validation 内部验证中 / beta 内测可用 / stable 稳定可交付 / deprecated 已废弃。

**C. 单次运行结果状态**（一次任务执行后的结论，见附录 B.3）：
- 执行状态：completed / failed / blocked_*；
- 验证状态：not_validated / numeric_checked / contract_verified / golden_matched。

产品范围已确认（A），不代表对应方法已经稳定（B）、也不代表某次运行科学验证通过（C）。执行成功不等于科学验证通过。不得把 draft、internal_validation 或 beta 方法包装为稳定临床结论；自动算法标签不得描述为已经人工确认。

#### A.2.1 关键术语
- **ArtifactManifest**：分析或仿真交付物的结构化清单，服务于结果交付与复现。

### A.3 数据生命周期不变量（唯一真源）
以下规则是全产品统一不变量：
- 原始数据不可被分析流程覆盖。
- 派生版本必须可追溯至原始数据、QC、预处理、方法与参数版本。
- 已完成备份集、其备份清单、文件哈希、完成时策略快照和历史 owner 记录不可被改写、覆盖或删除。
- 项目归档、软删除、结构变化、策略调整和 data owner 变化不得回溯改变或级联删除已完成备份集。
- 恢复必须生成新的可追溯对象，不得覆盖原备份集。

### A.4 存储服务边界
以下服务相互独立，不能互相替代：
- **活跃项目存储**：项目当前使用的数据和产物；
- **临时分析空间**：已交付分析结果的短期保存；
- **长期活跃存储**：用户选择持续保留的分析数据与结果；
- **文件同步**：可能传播误删除或损坏，不构成数据保护承诺；
- **原始数据备份存储**：独立、不可篡改的备份服务，不因其他存储删除、同步或损坏而级联删除。

分析工作流不得直接读写备份对象。

## 附录 B：方法工作流、QC、SafetyGate 与结果契约

本附录定义跨阶段的工作流与交付底线；专业模态可增加要求，不得降低这些底线。

### B.1 单方法工作流与方法 ID

每个单方法分析工作流只包含一种主要分析方法。不同方法分别创建工作流、分别运行、分别产出结果；云端收费阶段才按附录 F.1 规则产生独立计费明细。

一个工作流可包含该方法必要的公共步骤：
- 输入版本确认
- → QC
- → 引用或生成兼容预处理版本
- → SafetyGate
- → 一种主要分析方法
- → 结果校验
- → 图表、数据表和方法说明
- → 可复现记录
- → 制品和报告

内部调用多个函数或生成多张图，不等于多个方法。

方法 ID 必须包含模态、估计器、profile 和版本，例如：
- `scalp_eeg.psd.welch_resting@v0.1`
- `scalp_eeg.microstate.modified_kmeans@v0.1`
- `scalp_eeg.connectivity.wpli_alpha@v0.1`
- `scalp_eeg.pac.modulation_index@v0.1`

不得长期使用 psd、connectivity、pac、preprocess、report、pipeline 等同名不同义的含混 ID。每种具有独立科学含义的方法必须有独立方法 ID、工作流、输入输出契约、测试和生命周期。

### B.2 自动QC、自动去噪与 SafetyGate
QC 是所有分析的必经步骤。标准自动QC和自动去噪属于数据级公共能力；同一兼容清洗版本可供多个方法复用；同一兼容版本不得因选择不同方法重复生成。某方法确需不同预处理时，成本属于该方法工作流。（收费口径仅云端收费阶段适用，见附录 F.1.2；本地阶段不建设收费系统。）

本章描述的自动QC强度以头皮脑电专业分析的全量自动流程（ICA/ICLabel等）为基准。本地 V1（pc-qlanalyser 迁移功能）沿用其现有轻量人工复核逻辑，不要求本节自动QC体系，差异见附录 D.1。

头皮脑电专业分析默认以现有 QEEG Lab 自动流程为产品化基础：
- 自动坏导检测
- → 有空间坐标时坏导插值
- → notch
- → band-pass
- → 平均参考
- → 重采样
- → ICA + ICLabel
- → 安全阈值内自动排除伪迹成分
- → 坏段筛选
- → 清洗后QC
- → 原始时间映射
- → SafetyGate

- **AUTO_PASS**：满足最低自动处理要求，可继续分析，仍允许人工复核。
- **AUTO_PASS_BLOCKED**：必须明确记录阻断原因，不得伪装成自动通过。典型原因包括依赖缺失、ICA 拟合失败、ICLabel 不可用、电极位置缺失、坏导比例过高、自动排除成分过多、保留数据不足或方法缺少必要输入。

SEEG 和 ECoG 必须建立各自的 QC、参考和伪迹 profile，不能默认沿用头皮脑电专业分析流程。

### B.3 结果与可复现交付
每个分析或仿真工作流至少输出：结构化 JSON、CSV/TSV 数据表、SVG/PNG 科研图、HTML 报告、方法说明、参数快照与参数哈希、软件及依赖版本、输入输出哈希、QC/预处理记录、警告/错误/阻断原因、ArtifactManifest 和可导出结果包。PDF 在本地 V1为必交付项（迁移 pc-qlanalyser 既有报告引擎，见附录 D.1）；是否作为全部模态的标准交付仍待决策（见正文 9.2 第3项）。

每次运行必须分别标注执行状态、验证状态与方法生命周期（三类标签定义见附录 A.1）。执行成功不等于科学验证通过。

## 附录 E：云端权限、data owner、删除授权与审计

本附录只在线上阶段启用。其设计与开发须等待正文第9章所述线上启动条件确认；提前保留规则不代表与本地阶段同步建设。

### E.1 组织与权限原则
线上阶段采用最简有效的实验室协作控制，不建设飞书式复杂审批、联合导师、多层管理员、通用 RBAC、可配置策略引擎、字段级权限或复杂通知工作流。

所有云端资源必须有 organization_id。跨实验室的读取、导出、修改、归档、删除、授权和备份策略操作必须由服务端拒绝。前端展示不构成安全边界。

每个组织任一时刻有且仅有一名当前有效 PI。当前 PI 是动态组织主体，不将 PI 用户 ID 固化在项目授权表中。所有当前有效成员（PI、小导师、博后、研究生）都可以创建项目。

### E.2 PI、项目成员与项目删除
当前有效 PI 是组织内最高权限主体，可管理组织成员及身份、主要指导关系、全部项目与项目成员、项目负责人、项目删除授权、组织内全部项目数据、未来备份策略、data owner 转移、删除申请与项目归档/软删除；但该最高权限始终受附录 A.3 的数据不变量和附录 E.5 的审计不可变性约束。

云端首版项目成员仅分为项目负责人、协作者和只读查看者：
- 项目负责人默认等于创建者；仅 PI 可调整为同组织当前有效成员；
- 项目负责人和协作者在获授权后可查看项目、导入数据、运行分析、查看与导出结果；
- 只读查看者仅可查看项目和结果，导出是否开放由 PI 按项目设置；
- PI 可管理任意项目成员；
- 创建者、负责人和协作者均不因身份自动获得归档/软删除权。

首版仅支持一名由 PI 设置的主要小导师。指导关系只在创建研究生项目时生成"将该学生主要小导师加入删除授权"的默认建议；PI 确认或调整后，授权写入 project_delete_authorization_member_ids，成为固定项目授权。

项目归档/软删除的运行时唯一依据是当前有效 PI 或项目中有效的 project_delete_authorization_member_ids。小导师仅在本人为当前有效成员且被明确列入名单时，才可归档/软删除对应项目。博后和研究生无直接归档/软删除权。创建者、项目负责人和当前指导关系均不得作为既有项目的运行时删除权限来源。

学生换导师、导师身份调整、指导关系解除或成员状态变化，不自动修改既有项目删除授权；需由 PI 显式调整。

### E.3 删除申请、归档与软删除
所有当前有效成员可发起删除申请。申请至少记录项目、申请人、原因、时间、当前负责人、对数据/任务/结果/成员的影响摘要，以及"已完成备份集不受影响"的提示。

PI 可处理任意项目申请；被明确授权的小导师可处理其授权项目申请。云端首版处理结果仅为归档/软删除或拒绝，不实现多级审批、会签、催办或复杂通知。

云端首版的"删除"统一指归档/软删除。物理清理由独立数据保留规则处理；项目归档/软删除不得直接物理删除原始数据、结果、已完成备份集或审计日志。

### E.4 未来备份策略、data owner 与 PI 身份转移
未来备份策略仅影响后续新建备份集，不影响已完成备份集。当前有效 PI 可修改组织内任意数据对象/项目的未来备份策略，包括模式、范围、白名单、黑名单和 data owner。当前有效 data owner 仅可修改自己当前拥有的数据对象/项目的未来备份策略。非 PI 调用者的白名单/黑名单不得引用其所有权范围外的数据对象。

服务端必须校验调用者、策略对象及被纳入/排除对象属于同一 organization_id；非 PI 调用者必须是相关对象的当前 data owner。每条策略只能采用选择性备份或范围排除式备份之一，不得同时使用两类名单。

仅当 PI 明确将成员标记为离职、毕业或永久禁用等不可恢复状态时，触发 data owner 自动移交；登录异常、临时冻结、密码重置和普通安全校验失败均不得触发。系统将失效成员当前名下资源的 data_owner_member_id 原子地转移给该成员在失效时的有效主要小导师；不存在该关系、该小导师无效或不属于同一组织时，转移给当前有效 PI。移交只改变当前 data owner，不改变项目创建者、负责人、删除授权、指导关系历史和完成备份历史。PI 可直接指定同一组织的当前有效成员为新的 data owner。

PI 离职、毕业或永久禁用前，必须先将 PI 身份和组织所有权原子地转移给同一组织的一名当前有效成员。不存在合格继任成员时，服务端拒绝 PI 的离职或永久禁用操作。新 PI 立即获得最高管理权，原 PI 立即失去 PI 权限。

### E.5 审计不可变性
下列操作必须写入不可删除审计：创建/归档项目，删除申请及结果，项目负责人、成员与访问授权变化，主要指导关系变化，项目删除授权变化，未来备份策略与名单变化，data owner 移交，PI 身份/组织所有权转移和成员状态变化。

审计至少记录操作者或系统、原因、对象和 organization_id、变更前值、变更后值及时间；不得写入密钥、令牌、密码、原始文件内容或其他敏感凭据（去标识化与数据安全见附录 D.6）。任何角色均不得修改、覆盖或删除审计日志。云端首版仅 PI 可查看、搜索和下载组织级审计。

### F.3 QLanalyser Online 需求量级情景测算（内部、未验证）

| 参数 | 中性情景假设 | 当前证据状态 |
| --- | ---: | --- |

中性情景计算：


这里的 42.9 万数据小时是“可寻址分析时长”的情景估算；214.3 万元是假设全部可寻址时长均由 QLanalyser 按内部假设单价付费转化时的理论金额，不包含市场份额、付费转化率、折扣、免费额度、流失、服务成本和渠道分成，因此不能作为预期收入。正式测算至少还要补充目标客户覆盖率、实际设备活跃率、自由分析定义、付费转化率、客户留存、不同导联配置的使用结构和实际成交单价。

## 附录 G：备份状态机、恢复契约与安全要求

备份服务用于防止科研数据丢失，但本地阶段只验证流程和恢复模型，不构成设备级或场地级容灾承诺。本附录是备份状态机、范围、不可变性与恢复契约的唯一真源。

### G.1 目的、边界与状态机

**状态**：产品范围和备份模式规则已确认；本地阶段只验证备份流程与恢复模型，云端商业候选规则见附录 F.1，容灾验收底线见附录 E.6。

**目的与边界**：用于防止用户科研数据丢失（磁盘故障、误删除、设备丢失）。它不是项目/版本管理功能，不等同于云存储、文件同步、临时分析空间或长期活跃存储（存储服务边界见附录 A.4）。

备份以备份集为单位，而非孤立文件。每个备份集有稳定 ID、备份清单、哈希、大小和时间戳。上传流程为"上传→校验"。校验仅证明平台收到的字节与客户端提交的字节一致，不证明原始数据本身完整或正确。

备份状态机：待上传 → 上传中 → 待校验 → 校验通过 → 备份完成，以及失败/异常状态。"备份完成"是严格终态，完成后仍需持续或周期性完整性检查。恢复契约需明确恢复执行人、恢复位置、文件数、路径、大小和哈希与备份清单的一致性；具体恢复权限和目标路径见正文 9.2 第7项待决策。RPO/RTO 当前为 TBD/未承诺。

### G.2 备份范围与模式

**规则**：备份范围选择只决定哪些数据纳入后续新建备份集，不影响已完成备份集。本节账户、owner、PI 和 data owner 相关规则仅线上阶段启用；本地阶段仅验证不依赖账户与组织权限的本地备份/恢复流程模型。
- **选择性备份（白名单模式）**：用户显式勾选需要备份的项目/受试者/数据对象；后续新建默认不纳入，需手动勾选。
- **范围排除式备份（黑名单模式）**：默认将账户下全部项目的原始数据文件及分析结果/衍生数据纳入范围；用户可排除特定对象；后续新建默认自动纳入。新用户默认启用该模式。

原始数据文件与其对应的分析结果/衍生数据作为整体纳入或排除；不支持按数据类型单独勾选/排除。黑名单模式的排除和白名单模式的未勾选，只影响未来新建备份集。对对象执行"移出保护范围"时，必须使用"停止未来备份"或"移出保护范围"等措辞，不得使用"删除备份""清除备份""移除备份"。

首次启用或 owner 主动调整范围前，系统应展示新增/移除对象预览；新用户默认模式首次告知只表示已进入待备份范围，不表示已存在可恢复副本，具体以备份任务状态为准。线上阶段中 PI 与 data owner 对未来备份策略的权限，以附录 E.4 为唯一真源。

**安全承诺与阶段边界**：不得在实际验证前使用"永不丢失、绝对安全、永久保存、零数据丢失、随时即时恢复、已实现跨地域灾备"等表述。本地阶段的同盘同机备份仅代表"备份流程与恢复模型验证"，不构成设备级故障、磁盘损坏或场地灾难保护，不得宣称已具备容灾能力。线上真实容灾验收底线见附录 E.6；去标识化与数据安全以附录 D.6 为唯一真源。
