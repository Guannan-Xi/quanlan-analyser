
# WaveformWorkbench 客户最终版交互评审与整改方案（2026-06-28）

## 1. 评审定位

本评审把 `waveform-workbench.html` 当作面向客户的最终交互版本，而不是内部调试页。评审角色为：资深神经科学家、脑电分析专家、科研软件产品负责人、B2B 科研客户 UI 审核者。

目标用户：

- EEG/ERP/睡眠/认知神经科学实验室研究人员；
- 需要先浏览原始/预处理波形，再标记坏段、坏道、Reject/Remain epoch 的数据分析人员；
- 非临床、非诊断场景，只做科研数据准备。

核心任务：

1. 快速确认当前数据是否加载成功，是否为原始 EEG 的安全预览。
2. 像 EDFBrowser/传统 EEG 阅片软件一样连续浏览、翻页、缩放、调节振幅。
3. 看清事件/注释与波形关系，但不被事件线干扰波形判断。
4. 选中时间段或 epoch 后，明确知道下一步是 Reject、Remain、候选坏段、坏道还是撤销。
5. 所有写入都只进入准备草稿，不修改原始 EEG。
6. 最终能把草稿变成可追踪的数据准备方案，供后续 PSD/ERP/TFR/PAC 等分析使用。

参考依据：

- Google Labs `design.md` 思路：把目标用户、组件层级、交互状态、不要做什么和验收证据写入设计合同。
- 本地视觉/UX 规范：层级、排版、留白、色彩职责、状态体验、数据可视化可访问性。
- EEG 阅片习惯：波形优先、键鼠操作优先、浏览与写入模式分离、Reject/Remain 可撤销、有审计记录。
- 当前截图：`3b7992ef-128d-4ed4-a676-ca0134ddf8b1.png`。
- 当前源码：`frontend/waveform-workbench.html/css/js`。

## 2. 总体结论

当前版本已经达到“可用”，但还没有达到“客户最终版”。主要问题不是功能缺失，而是信息组织方式仍像工程控制台：控件堆叠、状态重复、主行动不够聚焦、专业术语解释不足、右侧处理面板层级偏乱。

成熟度判断：

```text
当前等级：good usability 的下沿
目标等级：polished and professional（科研客户可演示/公测）
```

必须优先修复的不是配色，而是“客户第一眼是否知道：我正在看什么、现在处于什么模式、下一步该做什么、哪些按钮为什么不可用”。

## 3. P0 问题（客户最终版阻断）

### P0-1 控件工具条过于平铺，浏览/显示/写入混在一起

现状：

- 浏览按钮、时间窗、事件显示、灵敏度、通道数、模式、Epoch 控件全部在同一工具条。
- “模式”组里同时有浏览、选段、Epoch 复核、候选坏段、坏道、快捷键，客户需要先理解所有概念才敢操作。
- 视觉上没有明显“当前工作阶段”：浏览波形 -> 选择对象 -> 处理草稿。

风险：

- 初次客户容易误点写入模式。
- 研究人员会觉得这是调参面板，而不是阅片工作台。
- 客户看教学数据时还没形成任务路径，就被大量控件打断。

整改：

- 把工具条重组为四组：
  1. 浏览：第一页、上一页、下一页、末页、时间窗。
  2. 显示：灵敏度、通道数、事件显示。
  3. 标注模式：浏览、选段、Epoch 复核、候选坏段、坏道。
  4. Epoch 设置：长度、显示数量。
- 每组增加短说明文案，不让客户猜“模式”和“Epoch”的含义。
- 当前模式使用更强的视觉状态，其他模式保留轻量按钮。

验收：

- 首屏一眼能看到“浏览”和“标注模式”是不同事情。
- 默认浏览模式不会写入草稿的提示必须可见。

### P0-2 状态信息重复且噪音大

现状：

- 顶部卡片、overview caption、meta chips、status chips 同时显示窗口、通道、采样率、缓存、加载区间。
- overview caption 中“已加载 0.0-60.0s, 0.0-24.0s, 1.9-25.9s...”会越滚越长，像日志。
- 底部 status chips 有十几个，客户需要横向扫读。

风险：

- 客户以为这些都是需要理解的科学结果。
- “已加载区间”暴露实现细节，降低专业感。
- 重要状态“浏览模式不会写入草稿”被大量 chip 淹没。

整改：

- 状态区分为两层：
  - 客户层：当前窗口、通道数、显示采样率、灵敏度、事件显示、草稿数量、是否安全写入。
  - 调试层：缓存区间、chunk 请求、prefetch 等只放到 data-testid 或隐藏调试信息，不默认显示。
- overview caption 改成一句人话：`全程 00:01:00 · 当前窗口 00:00:21-00:00:45 · 已缓存可连续浏览`。
- meta chips 最多显示 4-5 个关键 chip，不显示长串加载区间。

验收：

- 页面不出现长串缓存区间文本。
- 用户无需理解“chunk/cache”也能知道波形是否可连续浏览。

### P0-3 右侧操作面板主行动不够聚焦

现状：

- 右侧同时有“当前选择与处理”、状态徽标、提示文本、草稿框、主行动提示、Reject/Remain、候选、撤销/重做、清空。
- 无选区时仍展示大量禁用按钮，客户看到灰按钮会以为系统不可用。
- `Reject/Remain` 英文没有解释，容易被非英语客户误解。

风险：

- 研究人员不知道“先选段还是先点 Reject”。
- 禁用按钮太多，会产生失败感。
- 清空类危险操作与常规操作距离太近。

整改：

- 右侧改为三段式：
  1. 当前选择：无选择/选段/epoch 范围/坏道。
  2. 建议动作：根据模式给一个主提示。
  3. 草稿与历史：Reject、Remain、坏道、撤销、重做、清空折叠或弱化。
- 无选区时隐藏或弱化 Reject/Remain，不把禁用按钮作为视觉主角。
- 按钮文案改为：`剔除 Reject`、`保留 Remain`，并在帮助中解释 Reject=从后续分析排除，Remain=明确保留。
- 清空全部草稿放到“危险操作”分区，视觉上远离主行动。

验收：

- 无选区时，右侧第一视觉焦点是“请在波形上拖拽选择一段”，不是一堆灰按钮。
- 有选区后，Reject/Remain 才成为主要可点操作。

### P0-4 “事件线”视觉权重仍偏高

现状：

- 教学 oddball 数据事件密集，竖线很多。
- 事件线与波形颜色接近，容易让客户误以为波形被切断或数据不连续。

风险：

- 客户把事件 marker 当作数据断点。
- EEG 判断被事件线干扰。

整改：

- 默认事件显示从“简洁”进一步降噪：线更淡，只在 overview 或 hover/详细模式显示标签。
- 事件图例改名为“事件标记（非断点）”。
- 在教学数据说明中加一句：`竖线为实验事件标记，不代表数据中断。`

验收：

- 默认视图中波形比事件线更显眼。
- 客户能从图例/提示知道事件线不是断裂。

## 4. P1 问题（专业感和效率）

### P1-1 通道与灵敏度控件表达不够贴近 EEG 习惯

建议：

- `50 uV/row` 保留，但中文旁加“每行振幅”。
- `通道` 改为“显示通道数”。
- 状态 chip 用 `42 uV/row` 而不是只显示在滑条下。

### P1-2 缺少“数据来源/方法边界”的可展开说明

建议：

- 顶部边界保留：`科研数据准备，不用于诊断`。
- 加一个轻量说明：当前为预览降采样/显示采样，不改变原始数据；最终分析使用准备方案引用原始数据。

### P1-3 右侧草稿摘要太像日志

建议：

- 改成表格式摘要：当前选区、Reject 段数、Remain 段数、坏道、可撤销次数。
- 审计历史可以折叠，不要默认堆文字。

### P1-4 快捷键提示入口过弱

建议：

- `快捷键` 放在浏览组右侧或页面底部状态区。
- 帮助文案分行：浏览、缩放、振幅、模式、撤销。

## 5. P2 问题（后续精修）

- Canvas 标题“EEG 波形复核”可以改为“连续 EEG 波形（预览）”。
- 图例中英文混排应统一：`剔除 Reject`、`保留 Remain` 首次出现双语，之后中文为主。
- 移动端可以只支持查看，不承诺密集复核。
- 后续真实数据应增加文件信息弹窗：采样率、通道数、参考、时长、注释数量、显示降采样策略。

## 6. 本轮最小可实施整改包

为了不扩大范围，本轮只改独立 WaveformWorkbench 前端：

- `frontend/waveform-workbench.html`
- `frontend/waveform-workbench.css`
- `frontend/waveform-workbench.js`
- `scripts/e2e_waveform_workbench_module.mjs`

本轮不改：

- 后端算法和 chunk API。
- 主工作台 `frontend/app.js`。
- PSD/ERP/PAC/癫痫模块。
- router / Headroom / gateway / IPC / model route。

本轮具体动作：

1. 工具条分组重排，增加 group subtitle。
2. overview caption 去掉长串加载区间。
3. meta/status chip 减噪，只保留客户能理解的核心状态。
4. 右侧面板无选择时隐藏主处理按钮区；有选择时显示 Reject/Remain。
5. 图例和文案改为科研人员更容易理解的中文：剔除 Reject、保留 Remain、事件标记（非断点）。
6. 增加教学数据事件线说明。
7. E2E 增加：页面不出现长串缓存区间；无选区时主处理按钮区弱化/隐藏；事件非断点文案存在；首屏仍有波形；滚轮仍 cache_hit。

## 7. 验收标准

功能验收：

- 教学数据自动加载后首屏可见波形。
- 滚轮水平浏览仍为 cache_hit，不创建旧 QC task。
- 选段后 Reject/Remain 可用。
- 无选区时 Reject/Remain 不作为视觉主焦点。
- 浏览模式不会写入草稿提示清晰。

UI 验收：

- 工具条四组结构清晰。
- 长串缓存区间不在客户默认界面显示。
- 右侧面板能回答：当前选了什么、建议做什么、草稿里有什么。
- 图例说明事件线不是数据断点。
- 禁用按钮不造成“系统不可用”的第一印象。

科学/边界验收：

- 明确科研数据准备，不用于诊断。
- 明确草稿不修改原始 EEG。
- 明确显示采样/预览不等于改变原始数据。

测试证据：

- `node --check frontend/waveform-workbench.js`
- `node --check scripts/e2e_waveform_workbench_module.mjs`
- Playwright E2E passed。
- 首屏/滚动/选段/epoch 截图更新。
- 人工查看截图确认波形区仍为主视觉。

## 8. 设计合同摘要（DESIGN.md 等价）

- 波形是主角，控件必须服务波形判断。
- 默认模式必须安全：浏览不写草稿。
- 写入模式必须显式：选段/epoch/候选坏段/坏道都要有模式状态。
- 科研人员需要专业术语，但首次出现应有中文解释。
- 不把内部实现词（cache/chunk/prefetch）暴露给客户默认界面。
- 状态必须告诉客户下一步，而不是只显示系统状态。
- 危险操作必须远离主路径。
- 事件线不能压过波形，不能让用户误解为数据断裂。
