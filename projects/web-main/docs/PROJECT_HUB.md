## 1. 一句话定义

QLanalyser Online 是面向科研与 CRO 场景的在线 EEG 数据管理、分析和结果交付平台。产品目标是把非标准脑电分析转化为标准化、可复现、可审计、可商业运营的科研工作流。

硬边界：它不是医疗诊断、治疗建议、医疗器械或临床决策支持系统。

## 2. 当前主线

### 当前阶段

V1 付费试用版本：先完成真实可运行的客户闭环，再扩展分析方法和 CRO 质量体系。

### 核心用户闭环

```text
注册/登录
  -> 项目与受试者
  -> EEG 上传与元数据
  -> 数据质控/预处理准备
  -> 创建后台分析任务
  -> 结果复核
  -> 报告与结果包交付
  -> 余额/订单/发票/后台运营
```

## 4. 代码地图

| 区域 | 职责 | 关键入口/约束 |
|---|---|---|
| `frontend/` | 客户端、管理端、分析实验室和复核页面 | 当前为静态 HTML/CSS/JS；主入口 `index.html` / `app.js`；页面不得用静态展示冒充后端能力 |
| `backend/main.py` | FastAPI 应用装配 | 注册健康、账号、项目、受试者、文件、任务、结果、报告、计费、工作流和管理端路由 |
| `backend/api/` | HTTP 接口层 | 22 个已跟踪 Python 模块；负责鉴权、输入输出和错误边界，不承载重分析逻辑 |

| `backend/models/` | 请求、响应和持久化模型 | 项目、文件、任务、工件、报告、治理等数据契约 |
| `worker/` | 后台任务执行入口 | 长任务不得阻塞 HTTP；执行过程需保留参数、日志、状态和产物链路 |
| `eeg_core/io/` | EEG 文件读取 | 原始 EEG 文件不进入数据库；兼容性和大文件读取必须有明确失败状态 |
| `eeg_core/analysis/` | 科学分析实现 | 12 个已跟踪分析模块；稳定方法与实验室/测试方法必须分级 |
| `eeg_core/report/` | HTML/PDF/可复现性输出 | 报告必须能追溯源文件、参数、软件版本、任务和工件清单 |
| `scripts/` | 验收、构建、部署和证据生成 | 129 个已跟踪 `acceptance_*` 脚本；脚本数量不等于当前全部通过 |
| `deploy/` | Docker、Nginx、阿里云和运维材料 | 真实生产就绪必须有云端、备份恢复、HTTPS/CORS 和第三方回调证据 |
